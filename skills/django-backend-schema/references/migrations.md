# Django 数据库迁移

- 已提交或已部署的 migration 是数据库演进历史。除非用户明确要求修复历史迁移并确认影响，否则不要修改、删除或重命名它们。
- 结构变更先修改 Model，再使用 Django 的 makemigrations 生成新的 migration，并检查生成结果及依赖关系。
- 不要从零手写普通 schema migration。只有任务确实需要数据迁移或特殊数据库操作时，才在新的 migration 中添加相应操作，并说明原因。
- 数据库变更须保留向前迁移所需的历史链；不要为了让本地状态通过而重写已有环境的迁移历史。
- 生成迁移文件后，按任务要求验证；不要连接或迁移生产数据库。
