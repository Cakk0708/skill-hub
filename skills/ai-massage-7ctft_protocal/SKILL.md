# 岭阳屏幕 UART 文本通信协议

**协议版本：** V1.0  
**适用项目：** AI-Massage  
**通信设备：** 岭阳显示屏  
**通信方式：** UART 串口  
**协议类型：** 自定义二进制通信协议  
**文本编码：** GBK  
**校验方式：** 8 位累加和校验（Checksum-8）

---

## 1. 协议概述

本协议用于 AI-Massage 系统通过 UART 串口向岭阳显示屏发送文本内容，实现屏幕文字显示。

发送端需要将文本转换为 GBK 编码，并按照协议规定的数据帧结构组织字节数据，通过 UART 串口发送至显示屏。

屏幕接收到符合协议的数据帧后，解析文本内容并显示。

## 2. 文本通信协议结构

### 2.1 数据帧格式

文本显示指令采用以下数据帧结构：

```text
┌────────┬────────┬────────┬──────────────────┬────────┐
│ 帧头1  │ 帧头2  │ 长度   │ 文本数据         │ 校验码 │
├────────┼────────┼────────┼──────────────────┼────────┤
│  5B    │  A6    │  n     │ GBK + CRLF       │ Check  │
└────────┴────────┴────────┴──────────────────┴────────┘
   1字节    1字节    1字节      可变长度          1字节
```

### 2.2 字段定义

| 字段 | 长度 | 值 | 说明 |
|---|---|---|---|
| 帧头1 | 1 Byte | `0x5B` | 文本显示指令固定帧头 |
| 帧头2 | 1 Byte | `0xA6` | 文本显示指令固定帧头 |
| 长度 | 1 Byte | `n` | 数据帧长度标识，具体计算规则待确认 |
| 文本数据 | N Byte | GBK | 需要显示的文本内容 |
| 换行符 | 2 Byte | `0D 0A` | CRLF，按照协议追加在每条文本末尾 |
| 校验码 | 1 Byte | Checksum | 文本数据及换行符的 8 位累加和 |

**长度字段说明：**

已知设备示例中，长度字段为 `0x0B`，完整发送报文共 10 字节。

因此，当前尚不能确定长度字段是否表示完整帧长度、负载长度或包含额外偏移的协议长度。

在获得进一步确认前，不应将推测的长度计算公式作为正式实现规范。

## 3. 文本编码规则

### 3.1 编码格式

屏幕使用 GBK 编码显示中文文本。

发送端必须先将 Unicode 字符串转换为 GBK 字节序列，再参与后续数据帧封装。

示例：

| 文本 | GBK 编码（HEX） |
|---|---|
| 迪文 | `B5 CF CE C4` |
| 你好 | `C4 E3 BA C3` |

### 3.2 换行符

根据设备协议示例，每条文本末尾需要追加换行符：

```text
0D 0A
```

其中：

- `0D`：回车符（CR）
- `0A`：换行符（LF）

例如：

```text
文本：迪文
GBK：B5 CF CE C4

追加换行符：
B5 CF CE C4 0D 0A
```

## 4. 校验码规则

### 4.1 校验算法

根据已验证的串口数据，校验方式为 8 位累加和校验（Checksum-8）。

校验范围为：

**GBK 文本数据 + 换行符**

不包含帧头及长度字段。

计算公式：

```text
Checksum = SUM(文本数据所有字节) & 0xFF
```

即所有参与校验的字节求和后，仅保留低 8 位。

### 4.2 校验计算示例

发送文本：

```text
迪文
```

GBK 编码及换行符：

```text
B5 CF CE C4 0D 0A
```

校验计算：

```text
B5 + CF + CE + C4 + 0D + 0A
= 0x32D

0x32D & 0xFF = 0x2D
```

最终校验码：

```text
2D
```

校验码放置在数据帧末尾。

## 5. 完整通信示例

### 5.1 显示文本“迪文”

目标显示内容：

```text
迪文
```

完整 UART 发送数据：

```text
5B A6 0B B5 CF CE C4 0D 0A 2D
```

字段解析：

| 字节 | 含义 |
|---|---|
| `5B A6` | 文本显示指令帧头 |
| `0B` | 长度字段（设备示例值） |
| `B5 CF CE C4` | “迪文”的 GBK 编码 |
| `0D 0A` | 回车换行符 |
| `2D` | 校验码 |

**实际设备表现：** 岭阳显示屏显示“迪文”。

### 5.2 显示文本“你好”

目标显示内容：

```text
你好
```

GBK 编码：

```text
C4 E3 BA C3
```

追加换行符：

```text
C4 E3 BA C3 0D 0A
```

校验码计算：

```text
C4 + E3 + BA + C3 + 0D + 0A
= 0x33B

0x33B & 0xFF = 0x3B
```

参考数据帧：

```text
5B A6 0B C4 E3 BA C3 0D 0A 3B
```

**注意：** 此示例的长度字段 `0B` 暂按相同字节数的已知设备示例填写。完整数据帧尚需通过实际屏幕验证。

## 6. 通信处理流程

发送端处理流程：

1. 获取需要显示的文本字符串。
2. 将文本内容编码为 GBK 字节序列。
3. 在文本末尾追加 `0D 0A`。
4. 对文本数据及换行符计算 8 位累加和校验码。
5. 按协议要求确定长度字段。
6. 组装帧头、长度、文本数据和校验码。
7. 通过 UART 串口发送完整数据帧。

## 8. 协议实施建议

在 AI-Massage 系统中，建议将本协议作为独立设备通信协议进行封装，业务层不直接处理 GBK 编码、二进制帧及校验码。

协议实现时应注意：

- 统一使用 `bytes` 类型组织 UART 数据帧。
- 校验码按照原始字节值计算，不对十六进制字符串字符求和。
- 长度字段规则确认后，应增加边界值和最大长度校验。
- 对无法转换为 GBK 的字符，应显式处理编码异常。
- 增加已知报文的自动化测试，确保编码与校验结果正确。
