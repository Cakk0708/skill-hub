## 文档结构

- 接口文档统一输出到 `docs/api/`。
- 按 APP、子模块组织目录；每个接口单独使用一个 Markdown 文件。
- 文档记录真实的 URL、HTTP 方法、参数、权限要求、HTTP 状态码和响应体。
- 后端响应码和结构以 `.codex/rules/backend/api-response.md` 为项目规范；维护响应规范时同步更新本技能中的示例与编码表。
- 以当前实现和接口文档为依据。若现有接口与下方契约不一致，说明实际结构和差异，不要把预期格式伪写成当前实现。
- 新接口文档按下方响应契约说明；已有接口以真实实现为准，若存在差异则明确记录，不要在文档任务中擅自迁移接口。

## 统一响应外层

JSON 响应使用以下字段：

| 字段 | 类型 | 约定 |
|---|---|---|
| `code` | integer | 应用层结果码；`0` 表示成功，非零表示错误。 |
| `msg` | string | 面向人的简短说明；客户端不得依赖文案做分支判断。 |
| `data` | object 或 `null` | 成功时承载业务数据；错误时为 `null`。 |
| `errors` | array | 成功时为空数组；参数或字段错误可提供明细。 |
| `request_id` | string | 服务端提供时用于关联日志和排查问题。 |

成功响应示例：

```json
{
  "code": 0,
  "msg": "success",
  "data": {},
  "errors": [],
  "request_id": "req-abc123"
}
```

`code` 是应用层结果码，不替代 HTTP 状态码。成功返回相应的 `2xx`；错误返回匹配的 `4xx` 或 `5xx`，不能只用 HTTP `200` 表示失败。文档分别记录 HTTP 状态码和响应体 `code`。

## 整数结果码

结果码含义保持稳定，发布后不得改作他用。新增结果码时维护本表，并在对应接口文档中说明。

| 编码段 / 编码 | 含义 | 常用 HTTP 状态 |
|---:|---|---:|
| `0` | 成功 | `2xx` |
| `10000–19999` | 请求格式、参数和校验错误 | `400` / `422` |
| `10001` | 请求格式错误 | `400` |
| `10002` | 参数校验失败 | `422` |
| `10010` | 必填字段缺失 | `422` |
| `10011` | 字段格式无效 | `422` |
| `10012` | 字段值超出范围 | `422` |
| `20000–29999` | 认证和权限错误 | `401` / `403` |
| `20001` | 未认证或登录已过期 | `401` |
| `20002` | 无操作权限 | `403` |
| `30000–39999` | 资源查找错误 | `404` |
| `30001` | 资源不存在 | `404` |
| `40000–49999` | 业务规则和状态冲突 | `409` / `422` |
| `40001` | 违反业务规则 | `422` |
| `40002` | 资源状态冲突 | `409` |
| `40003` | 业务编号重复 | `409` |
| `50000–59999` | 服务端或依赖服务错误 | `5xx` |
| `50000` | 未预期的服务端错误 | `500` |
| `50001` | 依赖服务暂不可用 | `503` |

以上编码是当前项目的基础目录。未覆盖的错误按编码段分配新整数，并记录唯一含义；不要把 HTTP 状态码直接复制到 `code` 中。

## 列表成功响应

列表的 `data` 固定包含 `items` 和 `pagination`。`items` 始终是数组；无记录时返回 `[]`。`total` 是筛选后的总条数；页码从 `1` 开始；`total` 为 `0` 时 `total_pages` 为 `0`。

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "items": [
      {
        "id": 501,
        "code": "WO-20261003-001",
        "name": "装配工单",
        "status": "in_progress",
        "status_label": "进行中"
      }
    ],
    "pagination": {
      "page": 1,
      "page_size": 20,
      "total": 137,
      "total_pages": 7
    }
  },
  "errors": []
}
```

列表项可比详情精简；若字段同时出现在列表和详情中，字段名、类型和编码含义保持一致。状态等机器值与展示文本分开，例如 `status` 和 `status_label`。

## 详情成功响应

详情的 `data` 固定按页面数据区分成 `basic_data`、`other_data` 和 `document_data`。三个区块始终存在；空的对象返回 `{}`，无文档时 `document_data.items` 返回 `[]`。不要将数据库模型字段无差别地全部铺平输出。

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "basic_data": {
      "id": 501,
      "code": "WO-20261003-001",
      "name": "装配工单",
      "status": "in_progress",
      "status_label": "进行中"
    },
    "other_data": {
      "quantity": 120,
      "remark": "优先生产"
    },
    "document_data": {
      "items": [
        {
          "id": 901,
          "name": "作业指导书",
          "file_name": "assembly-guide.pdf",
          "content_type": "application/pdf",
          "size_bytes": 283841,
          "download_url": "/api/documents/901/download",
          "uploaded_at": "2026-10-03T09:30:00+08:00"
        }
      ]
    }
  },
  "errors": []
}
```

顶层 `code` 是响应结果码；`basic_data.code` 等业务字段是工单号、物料号等资源编码，两者含义不同。`document_data.items` 返回文件元数据和下载入口，不在 JSON 中返回文件二进制。

## 错误响应

错误响应的 `data` 为 `null`，顶层 `code` 为非零整数。字段级错误可在 `errors` 中给出字段路径、整数错误码和可读说明。

```json
{
  "code": 10002,
  "msg": "参数校验失败",
  "data": null,
  "errors": [
    {
      "field": "quantity",
      "code": 10012,
      "msg": "必须大于 0"
    }
  ],
  "request_id": "req-abc123"
}
```

服务端错误向客户端返回通用说明和 `request_id`；不要在响应中暴露堆栈、SQL 或内部异常细节。
