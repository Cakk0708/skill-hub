# 数据库、网络与迁移

MySQL、Redis 是依赖；应用发布不默认新建或重建数据服务。即使当前 Compose 声明数据服务，也先核实所有权、运行实例、版本、网络、逻辑库、卷、备份和应用可达性。只有本次明确选择数据服务发布/迁移时才执行对应变更，不从历史文档中的方案推定授权。

新布局使用根目录 .env.prod 统一配置，由 Compose environment 显式映射各服务必要变量。旧 env 文件不是目标规范；不能解析时从运行实例和受保护配置核对所需值，准备目标文件且不输出秘密。目标凭据、网络或挂载事实无法核实时停止切换。

- host 网络中的回环可指向宿主机；bridge 中回环仅指容器自身，使用核验的服务名与网络。
- 从每个需要存储的应用容器实测 MySQL/Redis；不通过开放公网端口解决连通性。
- 核对主机与云侧访问范围，不能把容器连通当成数据库不对公网暴露的证据。
- 目录标准不要求搬迁数据；既有卷和挂载先保持，搬迁须核实授权、备份及恢复路径。

无 schema 变更不运行 Alembic，记录 not_required。有迁移则先核实当前/目标 revision、兼容性、备份和恢复，manager-api 还要核对 Liquibase changeSet；事实不明停止，镜像回滚不自动 downgrade。

涉及存储依赖或连接池时，核对真实驱动版本与关键 API，用同一个单连接池连续两次 checkout 并 SELECT 1，验证 Redis PING。相关新容器至少观察 10 分钟，检查 degraded、writer delivery、连接池及数据库错误；异常不输出连接 URL 或完整异常中的凭据。
