## 协议概述

本协议用于 AI-Massage 系统通过 UART 串口向岭阳显示屏发送文本内容，实现屏幕文字显示。

当前交互版本的发送帧在旧版文本帧基础上增加了状态字段和占位字段。发送端需要将文本转换为 GBK 编码，并按照当前版本的数据帧结构组织字节数据，通过 UART 串口发送至显示屏。

屏幕接收到符合协议的数据帧后，解析文本内容并显示。

## 文本通信协议结构

### 数据帧格式

当前交互版本的文本显示指令采用以下数据帧结构：

| 帧头1 | 帧头2 | 长度 | 状态 | 占位 | 文本数据 | 换行符 | 校验码 |
|---|---|---|---|---|---|---|---|
| `5B` | `A6` | `n` | `n` | `n` | GBK | `0D 0A` | Checksum |

完整字段顺序为：

```text
5B A6 | length | status | reserved | GBK text | 0D 0A | checksum
```

旧版文本帧不包含“状态”和“占位”两个字段，格式为：

```text
5B A6 | length | GBK text | 0D 0A | checksum
```

旧版字段顺序不能直接用于当前交互版本。

### 字段定义

| 字段 | 长度 | 值 | 说明 |
|---|---|---|---|
| 帧头1 | 1 Byte | `0x5B` | 文本显示指令固定帧头 |
| 帧头2 | 1 Byte | `0xA6` | 文本显示指令固定帧头 |
| 长度 | 1 Byte | `n` | 数据帧长度标识，具体计算规则待确认 |
| 状态 | 1 Byte | `n` | 0: 无效、1: 待命中、2: 播报中、3: 聆听中 |
| 占位 | 1 Byte | `n`（已知示例为 `0x00`） | 占位字段，具体取值规则按当前交互版本执行 |
| 文本数据 | N Byte | GBK | 需要显示的文本内容 |
| 换行符 | 2 Byte | `0D 0A` | CRLF，按照协议追加在每条文本末尾 |
| 校验码 | 1 Byte | Checksum | 文本数据及换行符的 8 位累加和 |


**长度字段说明：**

已知当前交互版本设备示例中，长度字段为 `0x0B`。例如“迪文”报文为：

```text
5B A6 0B 02 00 B5 CF CE C4 0D 0A 2D
```

该示例实际包含 12 字节。`0x0B` 是否表示整帧长度、负载长度或包含额外偏移的协议长度，仍需以当前交互版本的正式长度定义为准，不能直接将其解释为整帧字节数。

因此，当前尚不能确定长度字段是否表示完整帧长度、负载长度或包含额外偏移的协议长度。

在获得进一步确认前，不应将推测的长度计算公式作为正式实现规范。

#### 文本数据规则

##### 编码格式

屏幕使用 GBK 编码显示中文文本。

发送端必须先将 Unicode 字符串转换为 GBK 字节序列，再参与后续数据帧封装。

示例：

| 文本 | GBK 编码（HEX） |
|---|---|
| 迪文 | `B5 CF CE C4` |
| 你好 | `C4 E3 BA C3` |

#### 换行符

根据设备协议示例，每条文本末尾需要追加换行符：

```text
0D 0A
```

其中：

- `0D`：回车符（CR）
- `0A`：换行符（LF）

例如：

```text
文本：迪文
GBK：B5 CF CE C4

追加换行符：
B5 CF CE C4 0D 0A
```

#### 校验码规则

##### 校验算法

根据已验证的串口数据，校验方式为 8 位累加和校验（Checksum-8）。

校验范围为：

**GBK 文本数据 + 换行符**

不包含帧头及长度字段。

计算公式：

```text
Checksum = SUM(文本数据所有字节 + 0D + 0A) & 0xFF
```

即对 GBK 文本和 CRLF 的原始字节求和后，仅保留低 8 位。当前定义不包含帧头、长度、状态和占位字段。

##### 校验计算示例

发送文本：

```text
迪文
```

GBK 编码及换行符：

```text
B5 CF CE C4 0D 0A
```

校验计算：

```text
B5 + CF + CE + C4 + 0D + 0A
= 0x32D

0x32D & 0xFF = 0x2D
```

最终校验码：

```text
2D
```

校验码放置在数据帧末尾。

### 完整通信示例

#### 显示文本“迪文”

目标显示内容：

```text
迪文
```

完整 UART 发送数据：

```text
5B A6 0B 02 00 B5 CF CE C4 0D 0A 2D
```

字段解析：

| 字节 | 含义 |
|---|---|
| `5B A6` | 文本显示指令帧头 |
| `0B` | 长度字段（设备示例值） |
| `02` | 状态码 |
| `00` | 预设占位符 |
| `B5 CF CE C4` | “迪文”的 GBK 编码 |
| `0D 0A` | 回车换行符 |
| `2D` | 校验码 |

**设备示例表现：** 岭阳显示屏显示“迪文”。

#### 显示文本“你好”

目标显示内容：

```text
你好
```

GBK 编码：

```text
C4 E3 BA C3
```

追加换行符：

```text
C4 E3 BA C3 0D 0A
```

校验码计算：

```text
C4 + E3 + BA + C3 + 0D + 0A
= 0x33B

0x33B & 0xFF = 0x3B
```

参考数据帧：

```text
5B A6 0B 02 00 C4 E3 BA C3 0D 0A 3B
```

**注意：** 当前交互版本的两个示例均沿用已知设备示例中的长度字段 `0B`；这不代表 `0B` 已被确认是整帧长度。

## 通信处理流程

发送端处理流程：

1. 获取需要显示的文本字符串。
2. 将文本内容编码为 GBK 字节序列。
3. 在文本末尾追加 `0D 0A`。
4. 对文本数据及换行符计算 8 位累加和校验码。
5. 按协议要求确定长度字段。
6. 组装帧头、长度、状态、占位、文本数据、换行符和校验码。
7. 通过 UART 串口发送完整数据帧。

## 通信返回结构（当前交互版本）

```
{帧头1} {帧头2} {长度} {数据}
```

| 字段 | 长度 | 值 | 说明 |
|---|---|---|---|
| 帧头1 | 1 Byte | `0x5B` | 固定帧头 |
| 帧头2 | 1 Byte | `0xA6` | 固定帧头 |
| 长度 | 1 Byte | `5` | 当前返回结构定义值 |
| 数据 | 1 Byte | `0` | 无效 |
| 数据 | 1 Byte | `1` | OK |
| 数据 | 1 Byte | `2` | Error |
