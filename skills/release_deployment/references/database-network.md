# 数据库与网络条件步骤

仅在本次发布涉及迁移、存储依赖、数据库/Redis 配置，或生产只读检查显示网络事实变化时读取。

## 数据服务归属和迁移决策

MySQL、Redis 是应用依赖，不默认属于 server/manager 镜像发布。线上已有实例时，先核对归属、版本、库名/逻辑库、监听、ACL、连接地址、备份、当前 schema revision 和每个应用容器的实际可达性。除非用户明确选择独立的数据服务部署，不启动仓库 all-in-one Compose 内的 MySQL/Redis，不新建专用实例、不覆盖现有数据。

仓库候选 `docker-compose_all.yml` 声明的 MySQL/Redis 服务和初始化卷不是线上事实。不得使用含 `latest` 数据库镜像或示例凭据的服务直接部署生产。需要独立迁移/重建数据库时，先做只读评估并准备可审查的变更、备份和恢复步骤；本技能的应用部署授权不包含创建账户、修改 MySQL/Redis 系统配置或执行数据清理。

迁移按本次目标涉及的 migration 逐个判断：

- 无结构变化：记录 `database_migration: not_required`，不运行 Alembic。
- 存在兼容迁移：核对目标库、当前 revision、目标 revision、连接路径、向后兼容性和备份方案后升级到明确 revision 或 `head`。
- 迁移事实、库名、权限、连接或备份能力不明：停止相关切换，不猜测。

迁移前数据库备份须限制权限并验证完整性。镜像回滚默认不做 downgrade；发布前确认新 schema 对上一镜像是否向后兼容。

读取数据库 URL 时直接从挂载的生产配置进入进程，不打印、不复制到命令参数或临时文件。不要输出完整 `.config.yaml`、密码、用户名或连接 URL。

## 网络判断

确认服务属于宿主机、同一 Compose 网络、其他容器网络或外部托管服务，并核对应用容器到 MySQL/Redis 的监听和实际连通性：

- `network_mode: host`：容器共享宿主机网络，`127.0.0.1` 可指向宿主机服务；不得同时配置冲突的 `ports`。
- bridge 网络：容器内 `127.0.0.1` 指向容器自身，不是宿主机。只能使用已验证的 Compose 服务名或宿主机可达地址。
- 宿主机 Redis 若只绑定 `127.0.0.1`，bridge 容器无法直接通过宿主机回环连接。任何监听、路由或防火墙调整都要单独核验授权，并限制到所需内部网络；不得通过开放 Redis 公网端口解决。
- MySQL/Redis 外部服务：只核实当前配置、权限和连通性，不擅自修改网络、防火墙或账户。
- full 的 manager-api 运行在 web 容器内；如果它需要存储，必须从该容器或同等网络命名空间实测，而不是只从宿主机测试。
- 同号端口是否冲突取决于网络命名空间；核对容器和宿主机实际监听，不仅看端口号。
- 当前网络正常且本次改动无关：保持现状，不做无关网络变更。

切换前确认 Compose、应用配置、路由与依赖拓扑一致；切换后从每个需要存储的重建应用容器验证 MySQL 和 Redis 可达性。应用连通性不能证明数据库端口没有公网暴露，另行核对云安全组和主机防火墙。

## 存储专项验收

涉及数据库依赖、连接池或存储运行时时，至少执行：

1. 核对镜像内 SQLAlchemy、数据库驱动和 Redis 客户端的真实安装版本。
2. 验证本次依赖修复所需的 API 或方法签名，不只检查 requirements 文件。
3. 使用单连接池连续两次 checkout，并分别执行 `SELECT 1`，验证第二次连接复用和 `pool_pre_ping`。
4. 从每个相关新容器执行 Redis PING。
5. 在不少于 10 分钟或实际问题触发窗口内检查 storage degraded、writer delivery、连接池、MySQL 和 Redis 错误；full 模式同时检查 manager-api 存储错误。

测试代码从挂载配置读取连接地址，但不得输出 URL、用户名、密码或完整异常中的凭据。验收失败时优先回滚应用镜像；是否回滚数据库结构是独立决策。
