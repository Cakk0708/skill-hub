
## RX 指令列表

主板收到 ESP32 的指令后，以相同功能码回复一帧，总帧长至少 20 字节（设置指令应答为 20 字节，`63` 综合状态查询应答为 25 字节）。Byte 4 的含义取决于对应 TX 的 Byte 4 是否为 `0xFE`：

```
5A A5 {总帧长} {功能码} {应答返回值 或 当前状态值} {数据区} {校验和}
```

| 对应 TX 的 Byte 4 | RX 的 Byte 4 | 说明 |
| -- | -- | -- |
| 非 `0xFE`（设置指令） | 应答返回值 | 见“设置指令应答返回值”，不回显下发的键值 |
| `0xFE`（查询指令） | 当前状态值 | 取值同 TX 指令列表中该功能码的参数定义；特殊功能码的数据区见“查询指令应答” |

### 设置指令应答返回值

适用于 TX 指令列表中全部功能码的非 `0xFE` 设置指令。

| 返回值 | 含义 | 执行结果 | 应答词 | 答复音频 |
| -- | -- | -- | -- | -- |
| `00` | 无效 | 未执行，指令或键值无效 | 当前无法执行此指令 | `voice_reply_not_executed.ogg` |
| `01` | 正常执行 | 已执行 | 沿用该指令原有的成功应答词 | 沿用该指令原有的成功答复音频 |
| `02` | 未开机不执行 | 未执行，主板处于未开机状态 | 按摩椅还没有开机，请先开机 | `voice_reply_power_required.ogg` |
| `03` | 当前状态不能执行 | 未执行，当前状态不允许该操作 | 当前状态下无法执行此指令 | `voice_reply_state_blocked.ogg` |
| `04` | 当前机型不支持 | 未执行，当前机型无此功能 | 此指令暂不支持 | `voice_reply_unsupported.ogg` |
| `05` | 执行不成功，已是极限值 | 未执行，目标值已在上限或下限 | 抱歉，不能再调节了 | `voice_reply_volume_limit.ogg` |
| -- | 设备与 esp32 连接异常 | 无法执行 | 设备无响应，请检查后再试 | `voice_reply_no_response.ogg` |

应答词说明：

- 应答词是面向用户的播报/显示文案，由返回值唯一决定，不随功能码变化；`01` 例外，使用各指令自己的成功应答词和答复音频。
- 答复音频统一存放在 `firmware/esp32-s3/main/boards/l01-iot-ci1302/assets/`，格式为单声道 OGG/Opus（16 kHz 输入、16 kbit/s、60 ms 帧），由 `firmware/esp32-s3/scripts/mp3_to_ogg.sh` 的参数转换，并由 `main/CMakeLists.txt` 按目录通配嵌入 L01 固件。
- `00`、`04` 沿用 L01 已有的离线提示文案；`02`、`03` 为新增文案和新增音频；`05` 复用音量到极限的音频 `voice_reply_volume_limit.ogg`。音量调节不经过岭阳主板，仍按原有本地逻辑播报。CI1302 离线词条和在线固定短命令收到对应返回码时播放上表音频；在线 MassageAgent 对话不在本地播放，返回码随执行回执的错误码上报服务端。
- 命令帧发出后主板没有任何回复（重发耗尽后终态为 `timeout` / `ACK_TIMEOUT`）时，使用“设备无响应，请检查后再试”（`voice_reply_no_response.ogg`）。`00~05` 之外的返回值不计为应答，同样以应答超时结束并使用该应答词。
- UART 发送失败等其他未确认结果仍使用已有的“指令执行未确认”（`voice_reply_unconfirmed.ogg`），不得套用上表任一应答词。

示例（功能码 `52`，线上 `0x34`）：

```
TX: 5A A5 14 34 4A 00 00 00 00 00 00 00 00 00 00 00 00 00 00 91
RX: 5A A5 14 34 01 00 00 00 00 00 00 00 00 00 00 00 00 00 00 48
```

- RX Byte 3 `0x34` 与 TX 功能码相同；RX Byte 4 `0x01` 为应答返回值“正常执行”，不是键值 `0x4A` 的回显。
- RX Byte 19 为校验和，按 `sum(frame[0..18]) & 0xFF` 计算，本例为 `0x48`。

解析注意：

- 应答返回值与状态值共用 Byte 4，且数值重叠（如 `01` 既可表示“正常执行”也可表示“开”）。必须依据对应 TX 的 Byte 4 是否为 `0xFE` 区分，只有 RX 而没有对应 TX 时不能判定其含义。
- 设置指令的应答不携带下发的键值，只能按“功能码 + 时序”与对应 TX 匹配，不能按“功能码 + 键值”匹配。
- `01` 表示主板已正常执行该指令；`00`、`02`、`03`、`04`、`05` 均表示未执行，应作为明确拒绝处理，不应等待超时。
- `00~05` 之外的返回值未定义，保留原始数值并按未知处理。
- 应答返回值不携带设置后的状态值。下发的是绝对键值时，`01` 即确认该键值已生效；下发的是相对调节键（如 `0x4A`/`0x4B`）时，调节后的状态仍须发送 `0xFE` 查询。
