## 共享引用

在实现前请阅读:

- **通用协议**: `../_shared/pen.md`

## 定位

根据已有设计稿实现前端页面。设计稿为视觉实现的唯一基准，除非用户明确允许调整。

## 遵循要求

- 开发之前检查 {root}/pen/ 是否存在对应设计稿。
- 阅读项目关联的 `pen/README.md` 与页面说明文档。
- 优先使用项目已有组件库，例如 Element Plus。
- 禁止未经批准擅自改变视觉方案。
- 实现后使用 Playwright 截图进行视觉对比与验证。

### 设计边界

- 严格还原设计稿布局、配色、字体、间距和交互状态。
- 设计稿缺失的业务交互允许补充，但不能随意改变既有视觉。
- 全部使用 mock 数据。
- 不得使用 svg、文字、emoj 作为图标，必须检查适合的 iconfont 方案。

## 工具边界

- 优先通过 Pencil MCP 工具读取页面节点、布局、样式及组件定义。

## 工程边界

- 视觉一致性：尽可能严格还原。
- 交互一致性：必须实现设计说明要求的状态与行为。
- 技术实现：遵循项目既有架构，不要求机械复制设计工具导出的代码。

## UI 控制协议同步（必做）

页面实现和视觉核对完成后，必须在本次任务中同步页面的 UI 控制协议：

1. 检查 `docs/ui-protocol/` 下现有的页面协议文件，按页面路由、页面组件名和文档内容确认是否已有目标页面协议。
2. 已有对应协议时，遵循 `ui-control-protocol-update` 做增量更新，保留未变化节点的英文 ID 和路径。
3. 没有对应协议时，遵循 `ui-control-protocol-create` 新建协议。
4. 协议必须反映最终实现的页面结构和交互节点；以完成后的前端实现为准，不要只照抄 Pen 设计稿中未实现或已变化的结构。
5. 直接在 `docs/ui-protocol/{页面名}.md` 创建或更新协议文件。页面名使用路由或页面组件名的 kebab-case 形式。不要创建 `map.md`、`layouts/` 或集中式 `design.md`。
6. 前端实现和协议文件都完成后，才算本 skill 的任务完成。最终说明对应的协议文件路径及本次协议变更。
