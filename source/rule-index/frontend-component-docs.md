## 组件文档同步维护规范

### 1. 适用范围

本规则适用于以下目录及其所有子目录：

- `*/src/components/`

### 2. 强制执行规则

当 AGENT 对上述目录内的文件进行**新增、修改、删除、重命名或移动**操作时，必须同步检查并维护该目录下的 `README.md` 文件。

具体要求如下：

1. **修改前阅读**：执行代码修改前，必须先阅读 `*/src/components/README.md`，了解现有组件结构、职责及文档约定。
2. **缺失时创建**：如果 `README.md` 不存在，必须创建该文件，并根据当前目录的实际内容编写说明。
3. **修改后检查**：完成代码修改后，必须检查 `README.md` 是否准确反映当前组件的结构与功能。
4. **按需同步更新**：当修改涉及以下内容时，必须更新 `README.md`：
   - 组件的新增、删除、重命名或移动。
   - 组件的功能、职责或使用场景发生变化。
   - 组件对外接口发生变化，包括 Props、Emits、Slots 等。
   - 组件的依赖关系或使用方式发生变化。
   - 原有文档内容与实际代码不一致。
5. **避免无效修改**：如果本次代码变更不影响文档的准确性，则无需修改 `README.md`，不得仅为了满足规则而产生无意义的文档变更。
6. **完成前验证**：任务结束前，必须确认 `README.md` 存在，且文档内容与当前代码保持一致。

### 3. 文档维护原则

- **准确性**：所有描述必须基于实际代码，不得虚构组件、功能或接口。
- **简洁性**：重点说明组件用途、组织结构、公开接口和使用方式，避免重复代码实现细节。
- **一致性**：遵循现有 `README.md` 的文档结构和 Markdown 风格。
- **及时性**：文档维护必须包含在当前开发任务中，不得无故延后。
- **最小变更**：优先更新受影响的文档内容，保留其他准确且有效的信息。

### 4. 任务完成要求

凡涉及适用目录的代码变更，AGENT 在结束任务前必须：

1. 确认已经阅读或创建 `README.md`。
2. 确认已根据代码变更完成必要的文档同步。
3. 在任务总结中说明 `README.md` 的处理结果（已创建、已更新或已检查无需修改）。

**本规则为强制性项目开发规范，即使用户未明确要求维护文档，也必须执行。**
