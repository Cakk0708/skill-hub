## 按摩主链路稳定架构约束

本文件只约束按摩主链路中长期稳定的架构边界。具体领域语义、协议字段、测试用例、构建命令和开发计划，分别以对应模块文档、测试和 `docs/plans/` 为准；路径级规则由 `.codex/rules/` 及对应技能负责。

### 在线对话主链路

在线用户对话和灵活自然语言按摩请求必须经过：

```text
在线语音对话或 APP 按摩请求
  -> backend/device-server 内嵌 MassageAgent
  -> 语义化执行计划和 MCP 编排
  -> ESP32 MassageController / MassageBoardAdapter
  -> 岭阳协议适配层
  -> UART
  -> 主板
```

主板返回的数据必须先在 ESP32 协议适配层完成拆包、校验和状态归一化，再以统一状态或执行回执返回服务端和用户。

CI1302 内置离线词条命中属于受限的本地命令入口，不属于在线对话链路。CI1302 按识别结果发送 `0x0101` 离线命令事件或 `0x0108` 人声录音事件；L01 ESP32 可通过 CI1302 UART1 发送 `0x0410` 当前网络状态通知（`0` 离线、`1` 在线），不得再经岭阳 UART0 主动推送该状态。该通知只同步网络状态，不改变 CI1302 事件入口约束。`0x0101` 可在云端会话在线或不可用时进入下文规定的窄范围按摩命令或 Wi-Fi 恢复例外；`0x0108` 只有在云端会话可用时才进入在线对话主链路。

### 语义层与协议层隔离

- MassageAgent 负责按摩自然语言理解、多轮对话、业务状态判断、安全规则、回复和执行计划；只能输出版本化的语义化按摩动作。
- MassageAgent 和 `backend/device-server` 不得依赖或生成岭阳功能码、键值、字节偏移、bit 位、校验和或 UART 原始帧。
- 服务端通常只向 ESP32 下发稳定的语义命令，不得重新引入第二套按摩对话决策链路。唯一允许的原始负载例外见下文“云端自动程序帧透传例外”。
- ESP32 的 `MassageController` 面向统一 `MassageCommand` 和 `MassageState`；`MassageBoardAdapter` 负责主板差异和协议编码。
- UART 层只负责字节传输，不理解按摩业务或主板功能码。
- 岭阳功能码、帧格式、校验、ACK、故障位及原始状态映射只能存在于 ESP32 岭阳协议适配层（当前为 `firmware/esp32-s3/main/massage/lingyang/`）。
- 更换主板只能替换或扩展 `BoardAdapter`，不得迫使 MassageAgent 修改业务动作格式。

#### CI1302 离线词条命令例外

- 例外仅适用于 CI1302 直接命中的内置离线词条结果 `0x0101`，不适用于普通人声录音 `0x0108`、任意用户文本或云端返回内容。
- 按摩命中枚举必须与版本化的按摩语义命令对应并受 ESP32 固定白名单约束。L01 的 `hit_enum=0x001C` 另有唯一的 v1 系统命令 `network.reconnect_saved`；该命令只恢复已保存的 Wi-Fi，不得映射成 `MassageCommand`。未知版本、未知枚举、重复事件或安全校验失败时不得执行。
- ESP32 为新 `0x0101` 事件保留本地事件 ID 用于去重。按摩语义命令进入现有 `MassageController` 和对应 `BoardAdapter`；`network.reconnect_saved` 只可在应用处于 Wi-Fi 配网状态、配置 AP 正在运行且存在已保存凭据时，经 `WifiBoard` / `WifiManager` 退出 AP 并尝试连接 Station。没有已保存凭据时只提示用户并保持配网状态，不停止 AP。该系统命令不得调用 `MassageController`、岭阳协议适配层或 UART0。
- 离线词条仅承载固定白名单中的确定操作，不新增本地多轮对话、开放式自然语言推理或第二套按摩状态判断链路。在线的通用对话及按摩语义仍由 MassageAgent 负责。
- `massage.stop` 仍最高优先级；只有主板回执或新鲜统一状态确认执行后才能反馈按摩命令成功。

#### 云端自动程序帧透传例外

- 仅限 UniCloud 自动程序推荐链路：用户先请求推荐，收到具体云端程序后明确确认启动，服务端才可将详情接口的 `program` 字符串作为不透明负载原样传到 ESP32。此例外不适用于 MassageAgent 生成的动作、任意用户输入、普通控制或其他云端字段。
- 服务端可以检查负载类型、非空和大小上限，并在服务端 / MCP 参数中以 `program_frames` 名称传递；不得拆分、解码、规范化、重排、校验岭阳帧内容、生成校验和或改写字符串。确认前不得下发。
- ESP32 MCP 和统一 `MassageCommand` 只保留该专用负载及必要的时长、`request_id` 元数据，不解释协议内容；Controller 仍负责新鲜状态、命令时效、幂等、队列和停止抢占。
- 只有 ESP32 岭阳 `BoardAdapter` 可以拆分并校验每个云端帧，再将校验通过的帧按原字节顺序逐帧交给 Controller / UART TX。整批帧须在发送前全部通过格式、长度、序号、终止标记和校验和检查；任一帧无效时整条命令零帧发送。
- 云端帧必须使用独立的 `self.massage.run_cloud_program` MCP 和独立命令类型，不能混入语义步骤程序入口。执行仍要求新鲜在线状态、设备无故障及适用的安全状态；逐帧等待主板回执，限制重试，最终通过新鲜统一状态确认完成，且 `massage.stop` 始终可抢占。
- UniCloud `program` 当前承载岭阳专用协议帧，因此这是一条明确、窄范围的主板专用例外。服务端不得据此新增其他裸帧接口；其他主板需要在各自适配器实现相应校验与传输。

### 统一接口约束

- 上行和下行使用带版本的语义化数据模型。
- 在线命令的 `request_id` 必须贯穿 MassageAgent、服务端编排、ESP32 和主板执行回执；离线词条命令由 ESP32 生成 `request_id` 并贯穿 Controller、适配层和主板执行回执。
- 未知状态必须保留为 `unknown` 及原始编号，禁止猜测成确定状态。
- 状态必须包含采集时间和递增 `revision`；服务端不得把过期状态当作当前状态。
- 单条 ACK 不是完整设备状态；局部回复必须合并到 ESP32 的状态快照后再上报。

### 按摩业务边界

- “模式”和“预设程序”必须保持不同概念；自动模式下的预设程序不能被表达为彼此独立的模式。
- 相对切换必须基于最新且有效的统一 `MassageState`；模式、程序或状态有效性未知时不得猜测目标，应查询状态或请求澄清。
- 语义动作必须表达业务意图，服务端不得使用主板功能码表达模式、程序或其他按摩业务。

### 控制与安全

- ESP32 必须校验服务端命令的参数、时效和安全约束，不能盲目执行。
- `massage.stop` 为最高优先级；普通命令队列不得阻塞停止动作。
- MCP 回调不得长时间阻塞 ESP32 应用主线程等待 UART。
- 在线按摩控制必须通过 ESP32 的语义命令/MCP 入口；离线按摩控制必须通过 CI1302 `0x0101` 白名单入口，并经过 `MassageController` 和 `BoardAdapter`，再调用 UART Transport。唯一的离线网络控制例外是 L01 `network.reconnect_saved`，它只通过 `WifiBoard` / `WifiManager` 管理 Wi-Fi，不接入按摩执行链路。

### 规则归属

- 岭阳协议字段、黄金报文、编解码和状态映射：放在岭阳协议模块文档与主机测试。
- 按摩词条、模式/程序语义和多轮对话行为：放在 MassageAgent 领域契约与回归测试。
- 执行回执状态、构建/烧录、真机联调和阶段顺序：放在对应执行协议、路径级规则和 `docs/plans/`。

不得为了临时演示让 MassageAgent 直接输出功能码、让服务端直接构造 UART 帧，或把业务协议重新写回通用 `UartComm`。
